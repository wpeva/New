# Гайд для чайников: свои IPv4-прокси на дешёвом VPS для легального парсинга

---

## 1. Краткое введение

### Что такое серверный IPv4-прокси простыми словами

Представьте, что вы отправляете письмо, но вместо своего обратного адреса указываете адрес посредника. Сайт видит не ваш домашний IP-адрес, а IP-адрес вашего сервера. Это и есть **прокси** — промежуточный сервер, через который идут ваши запросы в интернет.

**IPv4-прокси** — это прокси, работающий на обычном IPv4-адресе (формат вроде `185.23.45.67`). Вы арендуете дешёвый виртуальный сервер (VPS), ставите на него специальную программу, и она пересылает ваши запросы от имени этого сервера.

### Для каких легальных задач это нужно

- **Парсинг (сбор данных)** — автоматический сбор общедоступной информации с сайтов: цены товаров, объявления, погода, курсы валют. Важно: только то, что разрешено правилами сайта.
- **Тестирование** — проверка, как ваш собственный сайт выглядит из другого региона или страны.
- **Личная приватность** — скрытие вашего домашнего IP при работе в интернете.
- **Разработка** — тестирование API, проверка геозависимого контента на своих проектах.

### Риски и ограничения

> **Важно понимать:**
>
> - У каждого сайта есть **правила использования** (Terms of Service). Нарушение может привести к блокировке и юридическим последствиям.
> - Файл **robots.txt** на сайте указывает, какие разделы можно сканировать автоматически, а какие — нельзя. Всегда его соблюдайте.
> - Во многих странах есть **законы о персональных данных** (GDPR в Европе, ФЗ-152 в России). Собирать личные данные людей без их согласия — незаконно.
> - **Агрессивный парсинг** (сотни запросов в секунду) может расцениваться как DDoS-атака. Это уголовное преступление.
> - Этот гайд — **только для легального использования**. Автор не несёт ответственности за противоправные действия.

## 2. Минимальные требования и выбор VPS

### Какие параметры достаточны для старта

Для простого прокси-сервера, через который вы будете делать несколько десятков запросов в минуту, хватит самого дешёвого VPS:

| Параметр | Минимум | Комментарий |
|----------|---------|-------------|
| CPU | 1 ядро | Прокси почти не нагружает процессор |
| RAM | 512 МБ — 1 ГБ | 512 МБ хватит для 3proxy, 1 ГБ — с запасом |
| Диск | 10 ГБ SSD | Система + логи, больше не нужно |
| Трафик | 500 ГБ — 1 ТБ/мес | Для текстового парсинга этого более чем достаточно |
| ОС | Ubuntu Server 22.04 LTS | Стабильная, хорошо документированная |

### Нужен ли выделенный IPv4

**Да, обязательно.** При заказе VPS убедитесь, что в тариф входит **выделенный (dedicated) IPv4-адрес**. Это значит, что этот IP принадлежит только вашему серверу. Без него прокси не заработает — вам нужен адрес, к которому вы сможете подключаться снаружи.

Почти все VPS-хостинги дают один IPv4-адрес в базовом тарифе. Это то, что нужно.

### На что смотреть в тарифах, чтобы не переплачивать

1. **Трафик** — некоторые хостинги дают «безлимитный» трафик, другие считают каждый гигабайт. Для парсинга текстовых страниц 500 ГБ/мес — огромный запас. Но если у вас лимит 100 ГБ — следите за расходом.
2. **Локация сервера** — выбирайте сервер **ближе к целевым сайтам**. Если парсите российские сайты — берите сервер в России или Европе. Если зарубежные — в Европе или США.
3. **Не переплачивайте за мощность** — для прокси не нужен мощный CPU или 4 ГБ RAM. Берите самый дешёвый тариф.
4. **IPv4 в цене** — убедитесь, что выделенный IPv4 включён в стоимость, а не стоит дополнительно.

Ориентир по цене: от **2–5 $/мес** (или 150–500 руб/мес) за самый минимальный VPS.

## 3. Подготовка сервера (Ubuntu)

### 3.1. Как подключиться по SSH

SSH — это способ управлять сервером удалённо через командную строку. После покупки VPS хостинг пришлёт вам:
- **IP-адрес сервера** (например, `185.23.45.67`)
- **Логин** (обычно `root`)
- **Пароль** (или SSH-ключ)

#### На Linux / macOS

Откройте терминал и введите:

```bash
ssh root@185.23.45.67
```

Замените `185.23.45.67` на ваш реальный IP. Введите пароль, когда попросят.

#### На Windows

1. Скачайте и установите программу **PuTTY** (бесплатная) — или используйте встроенный терминал Windows 10/11.
2. **Через встроенный терминал Windows** (PowerShell или CMD):

```bash
ssh root@185.23.45.67
```

3. **Через PuTTY**: введите IP в поле «Host Name», порт `22`, нажмите «Open», введите логин и пароль.

### 3.2. Обновление системы

Первое, что нужно сделать на свежем сервере — обновить все пакеты. Это важно для безопасности.

```bash
apt update && apt upgrade -y
```

Что делает эта команда:
- `apt update` — скачивает свежий список доступных программ и обновлений.
- `apt upgrade -y` — устанавливает все обновления. Флаг `-y` означает «да, ставь всё без вопросов».

### 3.3. Создание отдельного пользователя

Работать под `root` (суперпользователем) постоянно — плохая практика. Создадим обычного пользователя:

```bash
adduser proxyuser
```

Система попросит придумать пароль и заполнить информацию (можно просто нажимать Enter, пропуская необязательные поля).

Дадим ему право выполнять команды от имени администратора:

```bash
usermod -aG sudo proxyuser
```

Теперь можно подключаться под этим пользователем:

```bash
ssh proxyuser@185.23.45.67
```

### 3.4. Настройка файрволла (UFW)

UFW — это простой файрволл (брандмауэр) для Ubuntu. Он контролирует, какие подключения к серверу разрешены.

```bash
# Разрешаем SSH (чтобы не потерять доступ к серверу!)
sudo ufw allow 22/tcp

# Разрешаем порты для прокси (мы будем использовать порты 3128-3132)
sudo ufw allow 3128:3132/tcp

# Включаем файрволл
sudo ufw enable

# Проверяем статус
sudo ufw status
```

Вы должны увидеть что-то вроде:

```
Status: active

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW       Anywhere
3128:3132/tcp              ALLOW       Anywhere
```

> **Внимание!** Всегда сначала разрешайте SSH (порт 22), а потом включайте файрволл. Иначе вы заблокируете себе доступ к серверу.

## 4. Установка и настройка 3proxy

Мы будем использовать **3proxy** — это бесплатный, лёгкий и простой прокси-сервер. Он отлично подходит для наших целей: мало весит, легко настраивается, поддерживает HTTP(S) и SOCKS5.

### 4.1. Установка 3proxy

Пошагово выполняем команды:

```bash
# 1. Устанавливаем инструменты для сборки
sudo apt install -y build-essential git

# 2. Скачиваем исходный код 3proxy
cd /tmp
git clone https://github.com/3proxy/3proxy.git

# 3. Переходим в папку проекта
cd 3proxy

# 4. Собираем программу из исходного кода
make -f Makefile.Linux

# 5. Создаём папки для 3proxy
sudo mkdir -p /etc/3proxy
sudo mkdir -p /var/log/3proxy

# 6. Копируем собранную программу в системную папку
sudo cp bin/3proxy /usr/local/bin/3proxy

# 7. Делаем файл исполняемым
sudo chmod +x /usr/local/bin/3proxy
```

Проверяем, что 3proxy установился:

```bash
/usr/local/bin/3proxy --help
```

Если появилась информация о программе — всё в порядке.

### 4.2. Создание файла с паролями

3proxy хранит логины и пароли в отдельном файле. Создадим его:

```bash
sudo nano /etc/3proxy/.proxyauth
```

Внутри файла напишите (каждая строка — отдельный пользователь):

```
user1:CL:password1
user2:CL:password2
```

Формат: `логин:CL:пароль`. `CL` означает, что пароль хранится в открытом виде (самый простой вариант для начала).

Сохраняем файл: нажмите `Ctrl+O`, затем `Enter`, затем `Ctrl+X`.

Ограничим доступ к файлу паролей:

```bash
sudo chmod 600 /etc/3proxy/.proxyauth
sudo chown root:root /etc/3proxy/.proxyauth
```

### 4.3. Создание конфигурационного файла

Теперь создаём главный конфиг 3proxy:

```bash
sudo nano /etc/3proxy/3proxy.cfg
```

Вставьте следующий конфиг:

```
# ===========================================
# Конфигурация 3proxy — простой HTTP/SOCKS5 прокси
# ===========================================

# --- Запуск от пользователя nobody (безопасность) ---
# Программа будет работать от имени непривилегированного пользователя
setgid 65534
setuid 65534

# --- Количество попыток DNS-резолва ---
nscache 65536

# --- Таймауты соединений (в секундах) ---
# Формат: timeouts <подключение> <ожидание первых данных> <ожидание следующих данных>
timeouts 1 5 30

# --- Логирование ---
# Записываем логи в файл, чтобы можно было посмотреть, что происходит
log /var/log/3proxy/3proxy.log D
# Формат: дата, время, IP клиента, URL запроса
logformat "- +_L%t.%. %N.%p %E %U %C:%c %R:%r %O %I %h %T"

# --- Авторизация ---
# Подключаем файл с логинами и паролями
users $/etc/3proxy/.proxyauth

# --- Правила доступа ---
# Разрешаем доступ только авторизованным пользователям
auth strong

# --- Ограничение количества одновременных подключений ---
maxconn 32

# --- HTTP(S)-прокси на 5 разных портах ---
# Каждая строка proxy запускает отдельный HTTP-прокси на указанном порту

# Порт 3128 — основной HTTP-прокси
proxy -p3128
# Порт 3129 — дополнительный HTTP-прокси
proxy -p3129
# Порт 3130
proxy -p3130
# Порт 3131
proxy -p3131
# Порт 3132
proxy -p3132

# --- SOCKS5-прокси (опционально) ---
# Если нужен SOCKS5 — раскомментируйте строку ниже и откройте порт 1080 в UFW
# socks -p1080
```

### 4.4. Разбор конфига — что делает каждая строка

| Строка | Что делает |
|--------|-----------|
| `setgid 65534` / `setuid 65534` | Запускает 3proxy от имени пользователя `nobody` — это безопаснее, чем запуск от `root`. Если кто-то взломает прокси, у него не будет прав администратора. |
| `nscache 65536` | Включает кеш DNS-запросов на 65536 записей. Ускоряет работу: не нужно каждый раз спрашивать DNS-сервер. |
| `timeouts 1 5 30` | Сколько секунд ждать: 1 сек на подключение, 5 сек на первый ответ, 30 сек на последующие данные. Если сайт не отвечает — соединение закроется, а не повиснет навечно. |
| `log ...` | Указывает, куда записывать логи. `D` — новый файл каждый день. |
| `logformat ...` | Формат записи в лог: время, IP, запрос и т.д. Помогает разбираться в проблемах. |
| `users $/etc/3proxy/.proxyauth` | Загружает пользователей из файла. `$` означает «прочитать из файла». |
| `auth strong` | Требует логин и пароль от каждого, кто подключается. Без пароля — не пустит. |
| `maxconn 32` | Не больше 32 одновременных подключений. Защита от перегрузки сервера. |
| `proxy -p3128` | Запускает HTTP-прокси на порту 3128. Через этот порт можно подключаться к прокси. |

### 4.5. Настройка прав на файлы логов

```bash
sudo chown -R nobody:nogroup /var/log/3proxy/
sudo chmod -R 755 /var/log/3proxy/
```

### 4.6. Создание systemd-сервиса (автозапуск)

Чтобы 3proxy запускался автоматически при перезагрузке сервера, создадим сервис:

```bash
sudo nano /etc/systemd/system/3proxy.service
```

Вставьте:

```ini
[Unit]
Description=3proxy Proxy Server
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/3proxy /etc/3proxy/3proxy.cfg
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Разбор:
- `After=network.target` — запускать только после того, как сеть будет доступна.
- `ExecStart=...` — какую команду запускать.
- `Restart=on-failure` — автоматически перезапускать, если 3proxy упадёт.
- `RestartSec=5` — ждать 5 секунд перед перезапуском.

Теперь активируем и запускаем:

```bash
# Перечитываем конфиги systemd
sudo systemctl daemon-reload

# Включаем автозапуск при загрузке сервера
sudo systemctl enable 3proxy

# Запускаем сервис прямо сейчас
sudo systemctl start 3proxy

# Проверяем статус
sudo systemctl status 3proxy
```

Если всё хорошо, вы увидите:

```
● 3proxy.service - 3proxy Proxy Server
     Loaded: loaded (/etc/systemd/system/3proxy.service; enabled)
     Active: active (running) since ...
```

Статус **active (running)** означает, что прокси работает.

## 5. Проверка работоспособности прокси

### 5.1. Узнаём внешний IP сервера

Подключитесь к серверу по SSH и выполните:

```bash
curl ifconfig.me
```

Эта команда покажет внешний IP вашего сервера, например: `185.23.45.67`. Запомните его — это IP вашего прокси.

### 5.2. Проверка через curl (в консоли)

С **вашего домашнего компьютера** (не с сервера!) выполните:

```bash
curl -x http://user1:password1@185.23.45.67:3128 http://ifconfig.me
```

Разбор команды:
- `curl` — утилита для HTTP-запросов.
- `-x http://user1:password1@185.23.45.67:3128` — использовать прокси с указанным адресом, портом, логином и паролем.
- `http://ifconfig.me` — сайт, который покажет, с какого IP пришёл запрос.

**Что должно получиться:** в ответ вы увидите IP вашего сервера (`185.23.45.67`), а **не** ваш домашний IP. Это значит, что прокси работает — запрос прошёл через сервер.

Если хотите проверить другой порт:

```bash
curl -x http://user1:password1@185.23.45.67:3129 http://ifconfig.me
```

Проверка SOCKS5 (если включили в конфиге):

```bash
curl --socks5 user1:password1@185.23.45.67:1080 http://ifconfig.me
```

### 5.3. Проверка в браузере

#### Firefox (самый простой способ)

1. Откройте **Настройки** → в поиске введите **proxy** → нажмите **Настройки сети** (или **Settings** → **Network Settings**).
2. Выберите **Ручная настройка прокси** (Manual proxy configuration).
3. В поле **HTTP-прокси** введите IP вашего сервера: `185.23.45.67`.
4. В поле **Порт** введите: `3128`.
5. Поставьте галочку **Использовать этот прокси для всех протоколов**.
6. Нажмите **ОК**.
7. При первом открытии любого сайта браузер попросит логин и пароль — введите `user1` и `password1`.

Проверить: зайдите на сайт `ifconfig.me` — он должен показать IP вашего сервера.

#### Chrome

Chrome использует системные настройки прокси, поэтому проще:
- **Вариант 1:** Используйте расширение **FoxyProxy** или **Proxy SwitchyOmega** — в нём можно указать IP, порт, логин и пароль.
- **Вариант 2:** Запустите Chrome с параметром из командной строки:

```bash
google-chrome --proxy-server="http://185.23.45.67:3128"
```

(Логин/пароль Chrome попросит при первом подключении.)

### 5.4. Как понять, что всё работает

| Проверка | Ожидаемый результат |
|----------|-------------------|
| `curl -x ... http://ifconfig.me` | Показывает IP вашего **сервера**, а не домашний |
| `sudo systemctl status 3proxy` | Статус `active (running)` |
| Лог `/var/log/3proxy/3proxy.log` | Появляются записи о ваших запросах |
| Браузер через прокси | Сайты открываются, `ifconfig.me` показывает IP сервера |

## 6. Рекомендации по безопасному и корректному использованию

### 6.1. Как не перегрузить VPS

Дешёвый VPS — это маломощный сервер. Не нагружайте его чрезмерно:

- **Ограничивайте потоки** — не запускайте больше 10–20 одновременных запросов через один прокси. В конфиге мы уже поставили `maxconn 32` — этого достаточно.
- **Следите за нагрузкой** — команда `htop` (или `top`) покажет, сколько ресурсов потребляет сервер:

```bash
sudo apt install -y htop
htop
```

- **Следите за трафиком** — если ваш тариф ограничен по трафику, проверяйте расход:

```bash
# Показывает трафик на сетевых интерфейсах
cat /proc/net/dev
```

### 6.2. Правила корректного парсинга

#### Всегда проверяйте robots.txt

Перед парсингом любого сайта откройте его `robots.txt`:

```
https://example.com/robots.txt
```

Этот файл говорит, какие разделы сайта разрешено сканировать ботам, а какие — нет. Пример:

```
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 10
```

Это значит:
- Нельзя заходить в `/admin/` и `/private/`.
- Между запросами нужно ждать не менее **10 секунд**.

#### Ставьте задержки между запросами

Даже если `robots.txt` не указывает `Crawl-delay`, **всегда делайте паузы**:

- Минимум **1–2 секунды** между запросами к одному сайту.
- Лучше **3–5 секунд** — так вы точно никого не побеспокоите.

Пример в Python:

```python
import time
import requests

proxies = {
    "http": "http://user1:password1@185.23.45.67:3128",
    "https": "http://user1:password1@185.23.45.67:3128",
}

urls = ["https://example.com/page1", "https://example.com/page2"]

for url in urls:
    response = requests.get(url, proxies=proxies, timeout=15)
    print(response.status_code)
    time.sleep(3)  # Пауза 3 секунды между запросами
```

#### Не сканируйте сайты агрессивно

- Не делайте сотни запросов в секунду — это похоже на атаку.
- Не скачивайте весь сайт целиком, если вам нужны только отдельные страницы.
- Указывайте в заголовке `User-Agent` информацию о вашем боте и контактные данные — это хороший тон.

### 6.3. Логирование: где смотреть логи

Логи 3proxy находятся здесь:

```bash
# Посмотреть последние 50 строк лога
sudo tail -50 /var/log/3proxy/3proxy.log

# Следить за логом в реальном времени (нажмите Ctrl+C для выхода)
sudo tail -f /var/log/3proxy/3proxy.log
```

Что можно увидеть в логах:
- Успешные подключения через прокси.
- Ошибки подключения (например, сайт не ответил).
- Попытки подключиться без пароля (возможные сканеры).

## 7. Масштабирование (простое объяснение)

### Когда пора расширяться

Вам нужно больше мощности, если:
- **Процессор загружен на 80–100%** — сервер не справляется с количеством запросов.
- **Трафик подходит к лимиту** — вы выбираете весь включённый объём трафика.
- **Нужно больше разных IP** — если один IP-адрес начал ограничиваться целевым сайтом (rate limit).

### Путь 1: Больше портов на одном IP

Вы можете добавить ещё портов в конфиг (например, 3133, 3134...) и создать больше учётных записей. Но помните:

- **IP-адрес останется тем же самым.** С точки зрения сайтов все ваши запросы идут с одного адреса. Больше портов не дадут больше IP.
- Этот путь полезен, если вы хотите дать доступ нескольким людям с разными логинами.

### Путь 2: Больше дешёвых VPS (рекомендуемый)

Самый эффективный путь — купить ещё несколько дешёвых VPS, каждый со своим IPv4-адресом. Тогда у вас будет пул из нескольких IP.

**Общий принцип:**

1. Арендуйте новый VPS (такой же дешёвый, 2–5 $/мес).
2. Подключитесь к нему по SSH.
3. Повторите все шаги из раздела 3 (обновление, пользователь, UFW).
4. Повторите все шаги из раздела 4 (установка 3proxy, конфиг, сервис).

Чтобы не делать всё вручную каждый раз, можно скопировать файлы настроек со старого сервера:

```bash
# С вашего компьютера: копируем конфиг на новый сервер
scp root@СТАРЫЙ_IP:/etc/3proxy/3proxy.cfg root@НОВЫЙ_IP:/etc/3proxy/3proxy.cfg

# Копируем файл паролей
scp root@СТАРЫЙ_IP:/etc/3proxy/.proxyauth root@НОВЫЙ_IP:/etc/3proxy/.proxyauth

# Копируем файл сервиса
scp root@СТАРЫЙ_IP:/etc/systemd/system/3proxy.service root@НОВЫЙ_IP:/etc/systemd/system/3proxy.service
```

После копирования на новом сервере:

```bash
sudo systemctl daemon-reload
sudo systemctl enable 3proxy
sudo systemctl start 3proxy
```

Теперь у вас два прокси-сервера с **разными IP-адресами**. Вы можете чередовать их в своём парсере (это называется **ротация прокси**).

Пример ротации в Python:

```python
import random
import time
import requests

proxy_list = [
    "http://user1:password1@185.23.45.67:3128",
    "http://user1:password1@91.55.12.34:3128",
    "http://user1:password1@45.67.89.10:3128",
]

urls = ["https://example.com/page1", "https://example.com/page2", "https://example.com/page3"]

for url in urls:
    proxy = random.choice(proxy_list)
    proxies = {"http": proxy, "https": proxy}
    response = requests.get(url, proxies=proxies, timeout=15)
    print(f"IP: {proxy.split('@')[1].split(':')[0]} -> {response.status_code}")
    time.sleep(3)
```

## 8. Типичные ошибки и их решение

### 8.1. Не работает подключение к прокси

**Чек-лист — проверяйте по порядку:**

1. **3proxy запущен?**

```bash
sudo systemctl status 3proxy
```

Если статус не `active (running)` — смотрите ошибку в выводе и в логах.

2. **Порт открыт в файрволле?**

```bash
sudo ufw status
```

Проверьте, что нужные порты (3128–3132) есть в списке `ALLOW`.

3. **Порт реально слушается?**

```bash
sudo ss -tlnp | grep 3proxy
```

Вы должны увидеть строки с вашими портами (3128, 3129 и т.д.). Если список пуст — 3proxy не запустился или конфиг неправильный.

4. **Правильные логин и пароль?**

Попробуйте подключиться с заведомо неправильным паролем. Если ответ тот же — возможно, авторизация не работает (проверьте путь к файлу паролей в конфиге).

5. **Хостинг не блокирует порты?**

Некоторые хостинги блокируют нестандартные порты на уровне своего файрволла. Проверьте панель управления хостинга или обратитесь в поддержку.

### 8.2. Прокси слушает только localhost (127.0.0.1)

Это значит, что прокси принимает подключения только с самого сервера, а не снаружи.

**Как проверить:**

```bash
sudo ss -tlnp | grep 3proxy
```

Если вы видите `127.0.0.1:3128` вместо `0.0.0.0:3128` — прокси слушает только локально.

**Как исправить:**

В конфиге 3proxy строка `proxy` без дополнительных параметров привязки слушает на всех интерфейсах (`0.0.0.0`). Убедитесь, что в конфиге **нет** строки вроде:

```
internal 127.0.0.1
```

Если есть — замените `127.0.0.1` на `0.0.0.0` или удалите эту строку:

```
# Слушать на всех интерфейсах (принимать подключения извне)
internal 0.0.0.0
```

После изменения конфига перезапустите 3proxy:

```bash
sudo systemctl restart 3proxy
```

### 8.3. Ошибки прав и перезапуск службы

**Как перезапустить 3proxy:**

```bash
sudo systemctl restart 3proxy
```

**Как остановить:**

```bash
sudo systemctl stop 3proxy
```

**Как посмотреть, что пошло не так:**

```bash
# Статус сервиса с последними строками лога
sudo systemctl status 3proxy

# Подробный лог системного сервиса
sudo journalctl -u 3proxy -n 50 --no-pager

# Лог самого 3proxy
sudo tail -50 /var/log/3proxy/3proxy.log
```

**Частые ошибки прав:**

- **«Permission denied» при запуске** — убедитесь, что файл 3proxy исполняемый:

```bash
sudo chmod +x /usr/local/bin/3proxy
```

- **Не может создать лог-файл** — проверьте права на папку логов:

```bash
sudo chown -R nobody:nogroup /var/log/3proxy/
sudo chmod -R 755 /var/log/3proxy/
```

- **Не может прочитать конфиг** — проверьте, что файл существует и доступен:

```bash
ls -la /etc/3proxy/3proxy.cfg
```

### 8.4. Краткая таблица диагностики

| Симптом | Вероятная причина | Команда для проверки |
|---------|------------------|---------------------|
| «Connection refused» | 3proxy не запущен или порт закрыт | `sudo systemctl status 3proxy` |
| «Connection timed out» | Файрволл блокирует порт | `sudo ufw status` |
| «407 Proxy Authentication Required» | Неправильный логин/пароль | Проверьте `/etc/3proxy/.proxyauth` |
| Прокси работает, но показывает домашний IP | Запрос идёт не через прокси | Проверьте настройки `-x` в curl |
| Высокая нагрузка CPU | Слишком много подключений | `htop`, уменьшить `maxconn` |

## Итого: минимальный план действий

Для тех, кто хочет быстро запустить прокси без чтения всего гайда — вот краткий чек-лист:

1. Купите дешёвый VPS (Ubuntu 22.04, 1 CPU, 512 МБ RAM, с выделенным IPv4) — от 2–5 $/мес.
2. Подключитесь по SSH: `ssh root@ваш_IP`.
3. Обновите систему: `apt update && apt upgrade -y`.
4. Установите 3proxy (раздел 4.1).
5. Создайте файл паролей (раздел 4.2).
6. Создайте конфиг (раздел 4.3).
7. Создайте systemd-сервис и запустите (раздел 4.6).
8. Откройте порты в UFW (раздел 3.4).
9. Проверьте через curl с домашнего компьютера (раздел 5.2).
10. Парсите вежливо: читайте robots.txt, ставьте задержки, не нагружайте сайты (раздел 6).

**Общее время от покупки VPS до рабочего прокси: 15–30 минут.**
